## Alternatives evaluation

- **Protocol-owned state registries / SSOT.** Landed choice: `docs/PROTOCOL.md` owns command lifecycle, local submission state, session axes, failure vocabulary, transitions, and race semantics (`feature-command-state-ssot.md:30`, `feature-command-state-ssot.md:62`). Alternatives: (1) leave state lists duplicated across foundation docs, optimizing local readability but preserving drift; (2) move immediately to generated IDL/schema as the only registry, optimizing generation but premature before contracts exist; (3) use formal models as the vocabulary registry, optimizing checked semantics but poor for product naming/wire evolution. Landed because Single Source of Truth requires one prose registry until generated contracts exist; later authority work made this precise: prose owns product intent and registry names, `.proto` owns wire shape, models own invariants (`docs/VERIFICATION.md:5`, `docs/VERIFICATION.md:13`).
- **`CommandState` membership and terminal split.** Landed choice: durable accepted-command states are `accepted`, `delivered`, `running`, and terminal `completed|rejected|failed|expired|cancelled|superseded`; `accepted` is the only initial durable state and terminal states are final (`docs/PROTOCOL.md:102`, `docs/PROTOCOL.md:119`, `docs/PROTOCOL.md:133`, `docs/PROTOCOL.md:134`). Alternatives: (1) smaller state set (`pending/running/done/failed`) optimizing implementation simplicity but collapsing operator-relevant distinctions; (2) larger adapter-specific state set optimizing harness fidelity but breaking adapter neutrality; (3) include local UI states in durable lifecycle, optimizing UI convenience but polluting durable protocol state. Landed because it preserves acceptance/delivery/execution/terminal distinctions while keeping adapter-specific and UI-only terms out of the core.
- **Control-surface-local submission state split.** Landed choice: `draft`, `submitting`, `submit_failed`, and local `unknown` are local-only; exits are a reconciled command id or rejected submission, not durable enum members (`docs/PROTOCOL.md:193`, `docs/PROTOCOL.md:209`, `docs/PROTOCOL.md:222`). Alternatives: (1) add `draft/submitting` to `CommandState`, optimizing end-to-end UI tracing but making unsent text durable protocol state; (2) model only HTTP request status, optimizing transport simplicity but losing reconcile semantics after unknown outcomes; (3) keep UI state unregistered, optimizing speed but allowing surfaces to diverge. Landed because durable truth begins only after acceptance and UI must reconcile rather than authoritatively infer.
- **Allowed transitions / no direct `accepted → completed`.** Landed choice: protocol transition graph permits `accepted → delivered|rejected|failed|expired|cancelled|superseded`, `delivered → running|completed|...`, and `running → completed|...`; direct `accepted → completed` is not in the stated registry (`docs/PROTOCOL.md:119`). Alternatives: (1) allow direct `accepted → completed`, optimizing quick local/read operations; (2) require `accepted → delivered → running → terminal` for every operation, optimizing uniformity but overstates quick actions; (3) keep graph loose and let adapters choose. Landed because accepted means durable-before-delivery, not target completion; even reads use lifecycle but may skip `running`, not delivery. Caveat: the checked seed model is broader; it permits any non-terminal to commit any terminal (`specs/seed/command_lifecycle.qnt:53`, `specs/seed/command_lifecycle.qnt:54`, `specs/seed/command_lifecycle.qnt:55`). Later docs now honestly classify the full transition graph as stated-normative, not checked (`docs/PROTOCOL.md:142`; `docs/VERIFICATION.md:61`), and `feature-formal-model-realignment` owns promotion of the exact adjacency rule (`feature-formal-model-realignment.md:26`, `feature-formal-model-realignment.md:48`).
- **`SubmissionOutcome` as pre-acceptance vocabulary.** Landed choice: pre-acceptance refusal is `SubmissionOutcome = rejected`, not `CommandState = rejected`; outcomes also include `accepted`, `failed`, and `unknown` (`docs/PROTOCOL.md:193`, `docs/PROTOCOL.md:199`). This was introduced during review to fix a blocker (`feature-command-state-ssot.md:72`). Alternatives: (1) fold submission refusal into `CommandState = rejected`, optimizing enum count but creating command records for invalid/unauthorized attempts; (2) single transport result enum for both pre- and post-acceptance, optimizing API surface but blurring durable lifecycle; (3) audit-only rejected attempts with no typed client outcome, optimizing persistence minimalism but weakening operator feedback/retry logic. Landed because acceptance creates a durable command only after validation, grant check, idempotency reconciliation, and target binding (`docs/PROTOCOL.md:368`, `docs/PROTOCOL.md:370`); clients need a boundary result without inventing durable command state.
- **First durable terminal commit wins.** Landed choice: terminal candidates race; the earliest valid terminal transition in durable LSN order wins, late candidates are audit/reconciliation events, and no global `cancelled > completed` priority exists (`docs/PROTOCOL.md:386`, `docs/PROTOCOL.md:389`, `docs/PROTOCOL.md:391`, `docs/PROTOCOL.md:395`). Alternatives and rationale are already fully covered by `feature-design-terminal-commit-race`: last-wins, priority-ordered, explicit conflict state, and hybrid override policy were considered and rejected/deferred (`feature-design-terminal-commit-race.md:24`, `feature-design-terminal-commit-race.md:53`, `feature-design-terminal-commit-race.md:64`). This audit cites that later design rather than duplicating the full race gate.
- **Layer-aware failure vocabulary.** Landed choice: failures are layer-aware and use the narrowest term; submission failures such as `validation_failed`/`authorization_denied` produce `SubmissionOutcome = rejected` with no `CommandState`, while delivery/execution/policy/reconciliation terms map to durable effects as appropriate (`docs/PROTOCOL.md:341`, `docs/PROTOCOL.md:347`, `docs/PROTOCOL.md:348`, `docs/PROTOCOL.md:356`). Alternatives: (1) flat `failed` enum, optimizing simplicity but hiding retry/authority semantics; (2) adapter-native error codes as protocol states, optimizing fidelity but breaking adapter neutrality; (3) HTTP/transport status as outcome authority, optimizing implementation but conflating transport with protocol. Landed because operators and conformance vectors need to distinguish validation, authorization, unsupported, transport timeout, execution failure, ambiguity, cancellation, expiration, supersession, and stale late events.
- **Session state axes.** Landed choice: session connectivity (`live|stale|offline|unknown|failed`) and activity (`idle|working|unknown`) are separate axes; UX composes labels rather than redefining protocol states (`feature-command-state-ssot.md:41`; `docs/UX.md:17`). Alternatives: (1) one enum such as `live/idle/working/stale/offline`, optimizing display but overloading freshness and work; (2) adapter-specific liveness labels, optimizing harness fidelity but divergent semantics; (3) no protocol registry, optimizing speed but making reconnect/snapshot correctness untestable. Landed because stale/unknown connectivity must dominate presentation and UI state is not authoritative.

## Faulty-assumption hunt

- **SSOT / authority split — holds.** Current first principles support the landed posture: project rules require one registry for state machines and protocol variants (`.agents/rules/code-design.md:6`), architecture says protocol owns state machines/failure vocabulary until generated contracts derive boundary artifacts (`docs/ARCHITECTURE.md:46`, `docs/ARCHITECTURE.md:193`, `docs/ARCHITECTURE.md:194`), and verification now partitions authority by question type (`docs/VERIFICATION.md:5`, `docs/VERIFICATION.md:13`). No accident-of-prose found.
- **CommandState registry and local split — holds.** The registry excludes local `draft/submitting` by design (`docs/PROTOCOL.md:102`) and durable acceptance remains visible until terminal (`docs/PROTOCOL.md:368`). UX consumes, not redefines, these registries (`docs/UX.md:9`, `docs/UX.md:15`). This survives today’s design gate.
- **Transition adjacency — holds-with-caveat, not a new fault.** The protocol norm forbids direct `accepted → completed` by omission (`docs/PROTOCOL.md:119`), while `command_lifecycle.qnt` permits it because `commitTerminal` accepts any non-terminal plus any terminal (`specs/seed/command_lifecycle.qnt:53`, `specs/seed/command_lifecycle.qnt:54`, `specs/seed/command_lifecycle.qnt:55`). This would be a faulty assumption if docs claimed the adjacency graph was checked. They do not: `docs/PROTOCOL.md` and `docs/VERIFICATION.md` both state the graph is stated-normative, not checked (`docs/PROTOCOL.md:142`; `docs/VERIFICATION.md:61`), and `feature-formal-model-realignment` explicitly tracks the V1 follow-on (`feature-formal-model-realignment.md:26`, `feature-formal-model-realignment.md:48`). Classification: designed/honestly disclosed tension after later correction, not an untracked duplicate finding.
- **SubmissionOutcome — holds.** Re-derived from boundary semantics: invalid submissions fail before durable command creation (`docs/PROTOCOL.md:370`), grant checks happen before acceptance (`docs/PROTOCOL.md:499`), and reserved/unknown kinds reject with `validation_failed` before grant evaluation (`docs/PROTOCOL.md:165`). Folding this into `CommandState = rejected` would make noncommands look like durable commands. The review-introduced fix is semantically sound; the missing alternatives record is supplied above.
- **Terminal race rule — holds.** The later design gate fully evaluated alternatives and ratified first durable terminal commit wins (`feature-design-terminal-commit-race.md:53`, `feature-design-terminal-commit-race.md:62`). The current model’s `lateTerminalCandidate` no-op checks terminal finality against allowed late candidates (`specs/seed/command_lifecycle.qnt:65`, `specs/seed/command_lifecycle.qnt:68`, `specs/seed/command_lifecycle.qnt:71`). No residual race-semantics debt beyond future vectors/model promotion confidence.
- **Failure vocabulary — holds.** `execution_outcome_unknown` was later refined as a failure-layer ambiguity signal mapping to `failed`, not a new `CommandState` (`docs/PROTOCOL.md:356`; `feature-idempotency-ambiguous-execution.md:43`). UX now derives retry safety from failure term plus adapter `idempotency_strength`, not from `CommandState` alone (`docs/UX.md:22`, `docs/UX.md:26`, `docs/UX.md:27`, `docs/UX.md:28`). This validates the layer-aware design and catches the main edge case.
- **Session axes — holds.** Session identity/generation work uses tombstones and `stale_event` late-event handling rather than mutating live state (`feature-session-identity-adapter-contract.md:43`, `feature-session-identity-adapter-contract.md:44`, `feature-session-identity-adapter-contract.md:59`). UX presents canonical session axes without redefining registries (`docs/UX.md:17`). No hidden state posture found.

## Verdict

**holds-with-caveats.** The foundational choices survive a design gate today: SSOT registry, local-vs-durable split, `SubmissionOutcome`, first durable terminal commit wins, layer-aware failures, and session axes are coherent with current foundation docs, models, and downstream dependents. The caveat is real but already honestly classified: `command_lifecycle.qnt` is permissive enough to allow `accepted → completed`, while the protocol forbids that adjacency. Current docs state that adjacency is **stated-normative, not checked**, and `feature-formal-model-realignment` owns promotion of the exact transition relation. No new faulty assumption or untracked propagation break was found.
