# Feature: Retroactive design-gate audit — v0 walking skeleton

## Brief

`feature-v0-walking-skeleton` slipped through to `done` tagged `[prose]`, structurally skipping the design gate (alternatives evaluation + faulty-assumption hunt). It is the most load-bearing foundational feature — 13 downstream dependents — and its "Required decisions" section (operator scope, deployment topology, persistence backend, first adapter/command kinds, control surfaces, explicit exclusions) is a list of genuine architectural choices, not settled prose.

This audit re-runs the design-gate-equivalent on those decisions and records the missing alternatives traceability, plus a faulty-assumption hunt and a propagation check across the 13 dependents.

## What to read

- The target: `.work/active/features/feature-v0-walking-skeleton.md` (read FULLY — its "Required decisions" and "V0 decisions to encode").
- The docs it produced: `docs/SPEC.md` (v0 walking skeleton section, non-goals), `docs/ARCHITECTURE.md` (v0 component slice), `README.md`.
- The 13 downstream dependents (propagation check surface): `feature-research-harness-action-surfaces`, `feature-command-state-ssot`, `feature-persistence-snapshot-model`, `feature-pi-parity-checklist`, `feature-ux-v0-acceptance`, `feature-research-web-control-security`, `feature-observability-operator-admin`, `feature-session-identity-adapter-contract`, `feature-security-threat-model`, `feature-research-contract-tooling`, `feature-operator-presence-and-action-inventory`, `feature-lease-scope-decision`, `feature-extension-seams-non-foreclosure`.
- Foundation context: `docs/VISION.md`, `docs/SPEC.md`, `docs/ARCHITECTURE.md`, `AGENTS.md`, `.agents/rules/`.

## Scope

For each load-bearing v0 decision, run:

1. **Alternatives evaluation.** Name 2-3 plausible alternatives, the tradeoff each optimizes for, and why the landed choice was taken. Record as the missing "rejected alternatives." Decisions to cover:
   - Operator scope: single-operator v0 (vs multi-operator / operator+observer).
   - Deployment topology: single authoritative core, no HA/clustering/split-brain (vs split-core / HA / leader-elected cluster).
   - Persistence backend: local durable store behind ports (vs mandated specific engine / vs remote-from-start).
   - First adapter + initial command kinds: Pi first, the initial OperationKind set (vs broader / narrower initial set).
   - Control surfaces: responsive web + CLI (vs native-first / CLI-only / web-only).
   - Exclusions: native mobile, HA, multi-operator provisioning, arbitrary adapters, leases (each — was excluding it a conscious choice with rationale, or an omission?).
2. **Faulty-assumption hunt.** Re-derive each decision from current first principles. Would the landed choice survive an honest gate today? Flag any decision that was an accident of the prose lane rather than a conscious choice. Pay special attention to: whether the single-operator assumption baked in anything that multi-human/`idea-multi-human-coordination` would have to reverse (not just defer); whether "backend behind ports" actually achieved Ports & Adapters or leaked an assumption; whether the initial OperationKind set was chosen against the harness action survey or asserted.
3. **Propagation check.** Examine the 13 dependents for any that silently assumed a posture the skipped gate would have surfaced as open. Specifically: did any dependent treat an exclusion as permanent architecture (the non-foreclosure failure), or assume a v0 scope choice was a timeless product decision?
4. **Verdict.** `holds` / `holds-with-caveats` (file refinement follow-up) / `faulty-assumption-found` (file corrective item with re-opening `depends_on`).

## Alternatives evaluation

- **Operator scope — landed: one human operator for v0.** Alternatives: (1) multi-operator/shared authority domains, optimizing collaboration and handoff readiness; (2) one operator plus read-only observer, optimizing lightweight multi-surface visibility; (3) organization/team provisioning, optimizing admin realism. The landed choice optimizes smallest executable trust surface while keeping actor, endpoint, grant, audit, and authority-domain seams explicit: the target feature states one operator with multi-human deferred but not foreclosed, current SPEC repeats that v0 has one operator while preserving multi-human concepts, and SECURITY labels future multi-operator coordination as a reserved seam (`.work/active/features/feature-v0-walking-skeleton.md:37`, `docs/SPEC.md:26`, `docs/SECURITY.md:25`, `docs/SECURITY.md:38`).
- **Deployment topology — landed: one authoritative coordination core.** Alternatives: (1) leader-elected cluster, optimizing availability; (2) active/active split-core, optimizing regional/federated scale; (3) colocated all-in-one daemon, optimizing install simplicity. The landed choice optimizes durable ordering and tractable first-terminal semantics while allowing surfaces/adapters to run separately: SPEC commits one authoritative core with no HA/split-brain, ARCHITECTURE allows split processes but a single writer, and the seams registry reserves HA/multi-core (`.work/active/features/feature-v0-walking-skeleton.md:38`, `docs/SPEC.md:27`, `docs/ARCHITECTURE.md:137`, `docs/ARCHITECTURE.md:158`, `docs/ARCHITECTURE.md:166`, `docs/PROTOCOL.md:594`).
- **Persistence backend — landed: local durable event/snapshot store behind ports.** Alternatives: (1) mandate a specific embedded engine, optimizing implementation certainty; (2) remote DB from the start, optimizing operational centralization; (3) in-memory/eventless MVP, optimizing speed of prototype. The landed choice optimizes crash recovery and Ports & Adapters: the target feature requires a local durable event/snapshot store behind ports, SPEC and ARCHITECTURE keep backend semantics engine-independent, and PROTOCOL requires local-first, port-isolated persistence with replay after crash (`.work/active/features/feature-v0-walking-skeleton.md:39`, `docs/SPEC.md:28`, `docs/ARCHITECTURE.md:138`, `docs/ARCHITECTURE.md:167`, `docs/ARCHITECTURE.md:168`, `docs/PROTOCOL.md:464`, `docs/PROTOCOL.md:465`, `docs/PROTOCOL.md:466`).
- **First adapter + command/action set — landed: Pi first; current registry-derived OperationKind set.** Alternatives: (1) Pi-only narrow commands, optimizing quickest workflow migration; (2) broad all-harness action catalog as implementation scope, optimizing future coverage but overbuilding v0; (3) generic message/command primitive, optimizing apparent simplicity but losing authority semantics. The original target used a narrow command list, but later research and design reopened it: harness survey found a six-class spine across seven harnesses and dropped generic no-grant Message for v0; the normative action inventory then produced committed `spawn`, `attach`, `instruct`, `cancel`, `interrupt`, `query`, `approval-response`, `elicitation-response`, `reconfigure`, `session-management` plus reserved `agent-send` and `adapter-utility-exec` (`.work/active/features/feature-v0-walking-skeleton.md:40`, `.work/active/features/feature-research-harness-action-surfaces.md:91`, `.work/active/features/feature-research-harness-action-surfaces.md:92`, `.work/active/features/feature-research-harness-action-surfaces.md:94`, `.work/active/features/feature-operator-presence-and-action-inventory.md:119`, `.work/active/features/feature-operator-presence-and-action-inventory.md:187`, `.work/active/features/feature-operator-presence-and-action-inventory.md:198`, `docs/SPEC.md:30`).
- **Control surfaces — landed: responsive web cockpit plus CLI admin/debug/scripted control.** Alternatives: (1) native mobile first, optimizing phone ergonomics; (2) CLI-only, optimizing implementation speed and scripting; (3) web-only, optimizing product focus. The landed choice optimizes immediate human-control-surface value across phone/laptop/desktop while retaining an admin/script path; later UX work reframed web as the first conformant surface under a surface-neutral floor, not the permanent closed set (`.work/active/features/feature-v0-walking-skeleton.md:41`, `docs/SPEC.md:11`, `docs/SPEC.md:31`, `docs/ARCHITECTURE.md:140`, `.work/active/features/feature-ux-v0-acceptance.md:48`, `.work/active/features/feature-ux-v0-acceptance.md:49`, `.work/active/features/feature-ux-v0-acceptance.md:57`).
- **Explicit exclusions — landed: native mobile, HA, multi-operator provisioning, arbitrary adapters, and leases out of the v0 executable slice.** Alternatives: implement each now; leave each unmentioned; or name each as a reserved/rejected seam. The landed posture is the third: native/mobile and other surfaces are reserved above the UX floor, HA/multi-core is reserved, multi-operator/federated authority is reserved, arbitrary adapter ecosystem support is outside v0 but adapter seams remain, and leases are `X (v0); R (future)` after a later lease decision (`docs/SPEC.md:34`, `docs/SPEC.md:38`, `docs/SPEC.md:40`, `docs/PROTOCOL.md:581`, `docs/PROTOCOL.md:588`, `docs/PROTOCOL.md:594`, `docs/PROTOCOL.md:617`, `.work/active/features/feature-lease-scope-decision.md:46`, `.work/active/features/feature-lease-scope-decision.md:55`).

## Faulty-assumption hunt

- **Operator scope: holds.** Re-derived today, single-operator v0 still minimizes security/provisioning scope while not baking in a one-human product: PROTOCOL keeps operator sessions actor/device/endpoint-bound for future multi-operator authority domains, SECURITY says data structures must not assume only one operator forever, and the extension checklist requires v0-only framing and parked-idea pressure testing (`docs/PROTOCOL.md:17`, `docs/SECURITY.md:38`, `AGENTS.md:67`, `AGENTS.md:78`). No reversal burden for `idea-multi-human-coordination` found.
- **Deployment topology: holds.** Single core remains the right v0 safety boundary because checked and stated models rely on durable ordering, LSNs, terminal finality, snapshots, and crash recovery; split deployment is preserved as process/network topology, while multi-writer/HA stays reserved (`docs/ARCHITECTURE.md:147`, `docs/ARCHITECTURE.md:158`, `docs/ARCHITECTURE.md:166`, `docs/VERIFICATION.md:27`, `docs/VERIFICATION.md:35`, `docs/VERIFICATION.md:451`). No hidden split-brain assumption found.
- **Persistence behind ports: holds.** The Ports & Adapters claim is now real, not just aspirational: ARCHITECTURE states control surfaces/adapters never touch persistence directly, PROTOCOL states port-isolated storage and replay semantics, and the persistence feature added snapshot tiers/degraded behavior after review (`docs/ARCHITECTURE.md:168`, `docs/PROTOCOL.md:465`, `docs/PROTOCOL.md:466`, `.work/active/features/feature-persistence-snapshot-model.md:44`). No backend engine leaked into domain semantics.
- **First adapter + OperationKinds: holds after later re-open.** The original narrow command list reads like the one place the prose lane could have over-asserted; however, `feature-research-harness-action-surfaces` and `feature-operator-presence-and-action-inventory` explicitly re-opened and resolved it against surveyed harness action surfaces, with reserved/rejected seams for non-operator senders, generic Message, and adapter utility exec (`.work/active/features/feature-research-harness-action-surfaces.md:87`, `.work/active/features/feature-research-harness-action-surfaces.md:91`, `.work/active/features/feature-operator-presence-and-action-inventory.md:123`, `.work/active/features/feature-operator-presence-and-action-inventory.md:124`, `.work/active/features/feature-operator-presence-and-action-inventory.md:125`, `.work/active/features/feature-operator-presence-and-action-inventory.md:147`, `.work/active/features/feature-operator-presence-and-action-inventory.md:200`). No corrective remains.
- **Control surfaces: holds.** Responsive web + CLI survives current first principles because UX now defines a surface-neutral conformance floor and explicitly rejects a pinned single visual design as the floor; native/mobile/skins are reserved seams, not foreclosed (`.work/active/features/feature-ux-v0-acceptance.md:61`, `.work/active/features/feature-ux-v0-acceptance.md:62`, `.work/active/features/feature-ux-v0-acceptance.md:98`, `docs/UX.md:5`, `docs/UX.md:51`).
- **Exclusions: hold.** Every exclusion is now classified rather than omitted: multi-operator/federated authority, native/desktop/notifications, HA/multi-core, arbitrary adapters beyond the Pi seam, agent-send/adapter utility exec, queued-message behavior, delegation, and leases appear in the extension seams registry with committed/reserved/rejected classifications (`docs/PROTOCOL.md:580`, `docs/PROTOCOL.md:581`, `docs/PROTOCOL.md:587`, `docs/PROTOCOL.md:588`, `docs/PROTOCOL.md:594`, `docs/PROTOCOL.md:605`, `docs/PROTOCOL.md:606`, `docs/PROTOCOL.md:607`, `docs/PROTOCOL.md:617`). Leases specifically were re-derived and deferred because single-operator/single-core v0 has no concrete lease use case and no fencing model should be designed speculatively (`.work/active/features/feature-lease-scope-decision.md:46`, `.work/active/features/feature-lease-scope-decision.md:48`, `.work/active/features/feature-lease-scope-decision.md:178`).
