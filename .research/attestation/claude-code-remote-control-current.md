# Attestation: Claude Code Remote Control

## Structural metadata

- Publisher/site: Anthropic Claude Code documentation.
- Page title observed: Continue local sessions from any device with Remote Control.
- Source kind: product documentation for remote control of Claude Code sessions.

## Paraphrased summary

Claude Code Remote Control connects web/mobile/Desktop surfaces to a Claude Code session running on the user's machine. The local session remains the execution environment; remote surfaces can send messages and view/sync the session. Server mode exposes spawn and capacity options. The source also documents trusted-device access, outbound-only transport, short-lived credentials, reconnect behavior, and limitations.

## Key passages

1. **Purpose and availability.** The page describes Remote Control as continuing a local Claude Code session from phone, tablet, or browser, and notes it is in research preview. Source anchor: lines 5-10.

2. **Local execution.** Remote Control connects claude.ai/code or Claude mobile apps to a Claude Code session running on the user's machine; when active, Claude keeps running locally, with local filesystem, MCP servers, tools, and project configuration. Source anchor: lines 13-22.

3. **Multi-surface sync.** The page says the conversation stays in sync across connected devices and messages can be sent from terminal, browser, and phone interchangeably. Source anchor: lines 17-20.

4. **Remote Control vs cloud.** The web/mobile interfaces are described as just a window into the local session, unlike Claude Code on the web running in cloud infrastructure. Source anchor: lines 20-22.

5. **Start modes.** The CLI/VS Code start section says sessions can be started in server mode (`claude remote-control`), interactive mode (`claude --remote-control` / `--rc`), from an existing session (`/remote-control` / `/rc`), or through VS Code. Source anchor: lines 39-113.

6. **Server-mode spawn/capacity.** Server-mode flags include `--spawn <mode>` with `same-dir`, `worktree`, and `session`, `--capacity <N>` for maximum concurrent sessions, and `--create-session-in-dir` to pre-create a session. Source anchor: lines 53-65.

7. **Resume options.** Server-mode flags include `--continue` to resume the most recent Remote Control session from the directory and `--session-id` to resume a specific session, with incompatibilities against spawn/capacity/session-creation flags. Source anchor: lines 57-61.

8. **Status and session list.** Active sessions expose a URL/QR code; remote session lists can show a computer icon with green status when online; titles can be explicit, renamed, derived from history, or autogenerated from hostname/prefix. Source anchor: lines 117-140.

9. **Auto-enable and multi-instance rule.** Remote Control activates only explicitly unless auto-connect is enabled; with auto-connect each interactive Claude Code process registers one remote session, while server mode supports multiple concurrent sessions from one process. Source anchor: lines 144-148.

10. **Transport/security.** The local session makes outbound HTTPS requests only, registers with Anthropic API and polls for work; traffic uses TLS and multiple short-lived credentials. Source anchor: lines 150-154.

11. **Trusted Devices.** Trusted Devices can require enrolled device plus recent sign-in before viewing or steering Remote Control sessions from web/mobile/Desktop. Source anchor: lines 156-169.
