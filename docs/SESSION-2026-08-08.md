## The headline: a protocol-doc contradiction, caught at the aggregate gate

The most consequential finding wasn't in any single feature — it was cross-cutting. `unsupported_command` was terminalizing as `FAILED` (adapter emits a failed RESULT → core maps to FAILED). The foundation review had explicitly **rejected** forcing `REJECTED`, reasoning that "the core canonically maps a failing RESULT to FAILED; FAILED + UNSUPPORTED_COMMAND is honest." That reasoning was wrong: it treated current core *behavior* as canonical, when the canonical source is `docs/PROTOCOL.md`, which unambiguously mandates `unsupported_command` → command `rejected` after acceptance (lines 181, 374, 124, 150). The epic aggregate review caught it; the fix overrode the foundation review's disposition and touched the core mapping + Pi alignment + the conformance vector. Phase 8 then caught the sibling (`delivery_rejected`, same table, same mandate) the aggregate fix had missed.

**Lesson:** when a reviewer adjudicates a protocol/state question against "how the code behaves," that's a red flag — adjudicate against the protocol doc (the canonical source), not the implementation. And when you fix one instance of a class (unsupported→REJECTED), immediately audit for siblings in the same seam (delivery_rejected).

## The cockpit-panel design: a honesty model evolved in conversation

The panel went through seven mock iterations. The decisive moment was the operator pushing back on a fabricated headline number ("pool remaining: 68%"). Verifying against token-commune's contract showed the pitch's "gateway is fully queryable → authoritative snapshots" claim was **false**: there's no pool-level capacity aggregate, capacity is per-contribution × per-window × nullable, `/commune/me` returns a display name not a stable id, events are latest-50 with no cursor, and there's no read-only credential scope. The honest tier is **PARTIAL**, not authoritative.

The locked honesty model (recorded in the cockpit-panel feature + the mock):
- **No derived pool-aggregate %.** Capacity shows only a real per-window reading (highest 5h utilization), labeled as Patchbay's display window.
- **The verdict is an owned Patchbay synthesis** (credential health + capacity + model availability), with its rule visible in the UI — never presented as native token-commune state.
- **Contributor attribution is the lead *external* prerequisite.** `/commune/pool` omits owners entirely; the observer ships honest-limited (unattributed counts) and gains a contributor view when token-commune adds attribution. The per-contribution drill-down is parked for that reason (not blocked — anonymous readings exist now; only the "who" is pending).
- **Credential-fresh ≠ telemetry-stale** (distinct axes); **stale ≠ live**; model IDs from the live catalog (`gpt-5.6` aliases are rejected upstream — use `gpt-5.5`/`gpt-5.3-codex-spark`); **no dynamic adapter renderer**.

The panel is the signed-off `option-7` — a calm per-pool list, adversarially reviewed.

## Decisions worth remembering

- **Adjudicate protocol/state questions against the protocol doc, not the implementation.** The unsupported→REJECTED override is the case study.
- **When you fix one instance of a failure-code class, audit the seam for siblings.** unsupported + delivery_rejected.
- **A labeled derivation is honest; a fabricated aggregate is not.** The line that mattered: capacity as "highest 5h utilization" (a real reading) vs "pool remaining %" (synthesized). The projection carries the raw per-contribution × per-window readings; only the cockpit derives a labeled display metric.
- **The conformance anti-pattern is durable.** Self-defining oracles, manufactured execution, redaction-scans-a-buffer, module-load-errors-as-kills, count-only-ledger guards — each recurrence is a Blocker. The self-validating-ledger discipline (data-driven, fail-closed on drift, validated against declarations not prose) is the fix shape, every time.
- **Mockup honesty reviews catch defects before production code.** The model-ID/capacity-claim issues would have shipped.
- **Core-neutrality held under pressure.** The narrow core changes (uncorrelated resource STATUS; delivery-refusal→REJECTED) use canonical primitives only — no token-commune vocabulary entered core, verified at every review tier.
